# หมวดหมู่สินค้า + สินค้าหลายลาย (store v2)

วันที่: 2026-10-14 · สถานะ: อนุมัติแล้ว (2026-10-14)

## ทำไม

ร้านใหม่ (`sumfu.store`) ตอนนี้ออกแบบมาขายแต่เสื้อ คือสินค้ามีตัวเลือกได้แค่ไซซ์กับสี และหน้า `/products` เป็นรายการเดียวยาวๆ ไม่มีหมวด
สโมสรนักศึกษาจะเริ่มขายสินค้าประเภทอื่นด้วย ตัวแรกคือ **พวงกุญแจ** ซึ่งมีลายแยกตามสำนักวิชา ลักษณะเดียวกับที่คาดผมสมัย Fresher Package 28
ทุกลายราคาเท่ากัน ต่างกันแค่ลายกับสต็อก

ลูกค้าต้องหาลายของสำนักวิชาตัวเองได้เร็ว โดยเลื่อนดูหรือค้นหาจากชื่อเต็มหรือตัวย่อที่นักศึกษาใช้กัน เช่น SCS ส่วน staff ที่ไม่ใช่ dev ต้องสร้างหมวดและเปิดขายสินค้าแบบนี้ได้เอง
หน้าตาเอาแนวทางมาจากเว็บ Apple

## เป้าหมาย

1. **หมวดหมู่ที่ admin จัดการเองได้:** สร้าง แก้ ลบ เรียงลำดับ ซ่อน/แสดง และตั้งรูปปกได้ ชื่อหมวดมีทั้งไทยและอังกฤษ
2. **สินค้าหลายลาย:** สินค้าหนึ่งชิ้น เช่น "พวงกุญแจ" มีหลายลายในตัว ทุกลายราคาเดียวกัน แต่ละลายมีชื่อไทย ชื่ออังกฤษ ตัวย่อ รูป และสต็อกของตัวเอง
3. **หน้าร้าน:** มีแถบหมวด หน้าหมวดพร้อมปก การ์ดลายละใบ ค้นหาด้วยชื่อไทย ชื่ออังกฤษ หรือตัวย่อได้ และกดการ์ดแล้วไปหน้าสินค้าที่เลือกลายนั้นไว้ให้แล้ว
4. **มือถือใช้งานได้ดีทั้งร้าน:** ทุกหน้าของหน้าร้านต้องจัด layout เหมาะกับจอมือถือ ผู้ใช้ย้ำเรื่องนี้ ไม่ใช่แค่หน้าที่สร้างใหม่ (ดู "ไล่ตรวจมือถือทั้งร้าน")
5. **หน้าตาไม่เหมือน AI สร้าง:** หน้าที่ออกแบบใหม่ต้องผ่านขั้นออกแบบ UX/UI ก่อนเขียนโค้ด (ดู "ขั้นออกแบบ")

## ไม่ทำ (non-goals)

- ระบบ FP28 เดิม (`admin.sumfu.xyz`, ออเดอร์ `FP28…`) ไม่แตะ
- ไม่มีปุ่มเติมรายชื่อสำนักวิชาให้อัตโนมัติ admin พิมพ์ชื่อไทย ชื่ออังกฤษ และตัวย่อเองทุกลาย (ผู้ใช้ตัดสินใจ)
- ไม่ทำราคาต่างกันรายลาย และไม่ทำเวลาเปิด-ปิดขายรายลาย ทุกลายใช้ราคาและรอบขายของสินค้า
- ไม่ทำหมวดซ้อนหมวด (sub-category) และสินค้าหนึ่งชิ้นอยู่ได้แค่หมวดเดียว
- ไม่ทำแท็ก ตัวกรอง หรือการค้นหาข้ามทั้งร้าน การค้นหามีเฉพาะในหน้าหมวด

## ห้ามเกิด (anti-goals)

- admin ที่สร้างเสื้อเป็นแล้วต้องไม่ต้องเรียนวิธีใหม่ flow ไซซ์/สีต้องเหมือนเดิมทุกอย่าง
- ออเดอร์ สต็อก และรายงานเดิมต้องไม่เพี้ยน ออเดอร์เก่าต้องแสดงผลเหมือนเดิม
- หน้าร้านบนมือถือต้องไม่ล้นจนเลื่อนแนวนอนได้ และต้องไม่มีปุ่มเล็กจนกดยาก

## หน้าร้าน

### `/products`: หน้ารวม

- **แถบหมวดด้านบน:** แบบ Apple Store มีไอคอนหรือรูปเล็กกับชื่อหมวด เลื่อนซ้าย-ขวาได้บนมือถือ ช่องแรกเป็น "ทั้งหมด"
- **ใต้แถบ:** การ์ดปกของแต่ละหมวด กดแล้วเข้าหน้าหมวด
  - บน desktop เรียงเป็นตาราง
  - บนมือถือเรียงลงทีละใบเต็มความกว้าง
- ใต้การ์ดปกจะมีรายการสินค้าทั้งหมดต่อหรือไม่ **ผู้สร้างตัดสินเอง**

### หน้าหมวด

URL: `/products/c/[categorySlug]` หรือรูปแบบอื่นที่ไม่ชนกับ `/products/[slug]` ผู้สร้างเลือกเอง

- **ปกหัวหน้า:** รูปปก ชื่อหมวด และข้อความบนปก ตามภาษาที่เลือก
- **ช่องค้นหา:** ติดอยู่ด้านบนตอนเลื่อน (sticky)
  - กรองฝั่ง client ทันทีที่พิมพ์
  - จับคู่กับชื่อไทย ชื่ออังกฤษ และตัวย่อของลาย รวมถึงชื่อสินค้าด้วย
  - ไม่สนตัวพิมพ์เล็ก-ใหญ่ และไม่ต้องพิมพ์ครบคำ
- **ตารางการ์ด:**
  - สินค้าแบบไซซ์/สี ได้การ์ดเดียวเหมือนตอนนี้
  - สินค้าหลายลาย **แตกเป็นการ์ดลายละใบ** มีรูปของลาย ป้ายตัวย่อ ชื่อตามภาษาที่เลือก และราคา ลายที่หมดขึ้นว่า "หมดแล้ว" และรูปจางลง
  - มือถือ 2 คอลัมน์ desktop 3–4 คอลัมน์
- **ค้นหาไม่เจอ:** แสดงข้อความว่าไม่พบ

### หน้าสินค้า `/products/[slug]` ของสินค้าหลายลาย

- **เปิดลายจากลิงก์:** ลิงก์จากการ์ดลายระบุลายที่เลือกไว้ เช่น `?design=<ตัวย่อหรือ id>` ผู้สร้างเลือกรูปแบบเอง แต่ลิงก์ต้องแชร์ต่อแล้วเปิดเจอลายเดิม
- **ข้อมูลที่แสดง:**
  - ชื่อสินค้าตัวเล็กอยู่ด้านบน เช่น "พวงกุญแจ"
  - ชื่อลายเป็นหัวข้อใหญ่
  - ราคาและสต็อกที่เหลือ
  - รูปใหญ่เป็นรูปของลาย ถ้าลายไม่มีรูป ใช้รูปรวมของสินค้าแทน
- **แถบ "ลาย":** เป็นรูปเล็กหรือป้ายตัวย่อเรียงกัน แบบเลือกสี iPhone
  - กดแล้วสลับลายในหน้าเดิม และ URL เปลี่ยนตาม
  - ลายที่หมดจะจางและกดซื้อไม่ได้
  - บนมือถือเลื่อนซ้าย-ขวาได้
- **บนมือถือ:** ปุ่ม "ใส่ตะกร้า / ซื้อเลย" ติดด้านล่างจอ ใช้กับหน้าสินค้า **ทุกชิ้น** รวมเสื้อ (ผู้ใช้ตัดสิน) ต้องเว้นพื้นที่ด้านล่างไม่ให้บังเนื้อหาและ footer
- **โหมดดูตัวอย่างตอนร้านปิด:** ยังต้องใช้ได้เหมือนเดิม (`useStorePreview` ใน `ProductDetail`)

### ตะกร้า / checkout / ออเดอร์

- ชื่อตัวเลือกในตะกร้าและในออเดอร์ (`variant_label`) ของสินค้าหลายลายคือ "ตัวย่อ · ชื่อลาย" หรือแบบที่ผู้สร้างเห็นว่าอ่านง่าย **ต้องเป็น snapshot ตอนสั่ง** เหมือนตอนนี้
- **snapshot 2 ภาษา (ผู้ใช้ตัดสิน):** `store_order_items` เพิ่มคอลัมน์ชื่อสินค้าอังกฤษและชื่อตัวเลือกอังกฤษ (nullable) คอลัมน์เดิม `product_name` / `variant_label` เป็นภาษาไทยเหมือนเดิม
  - หน้าออเดอร์ หน้าเช็คออเดอร์ และหลังร้าน แสดงตามภาษาที่เลือก ถ้าคอลัมน์อังกฤษว่าง (ออเดอร์เก่า หรือ admin ไม่ได้กรอก) ให้ใช้ภาษาไทย
  - เป็นการแตะ schema ตารางออเดอร์ ทำได้แค่ `ADD COLUMN` เท่านั้น ห้ามแก้หรือเติมข้อมูลในแถวเดิม และต้อง backup ด้วย `sqlite3 .backup()` ก่อน deploy
- สต็อกตัดรายลาย กลไกเดิมตัดราย variant อยู่แล้ว

### ภาษา

- ข้อความคงที่ทุกตัวเพิ่มใน `src/lib/storeI18n.ts` ทั้ง EN และ TH
- ชื่อหมวด ชื่อสินค้า และชื่อลายเลือกตามภาษาที่ลูกค้าเลือก (`useLang()`) ถ้าภาษานั้นว่าง ให้ใช้อีกภาษาแทน

### ไล่ตรวจมือถือทั้งร้าน (ผู้ใช้ตัดสิน)

นอกจากหน้าที่ทำใหม่ ให้ไล่ตรวจและแก้ทุกหน้าของหน้าร้านที่ความกว้าง 375px และ 320px:
- หน้าแรก (ทุกบล็อกใน `HomeBlocks`)
- `/products`, หน้าหมวด, `/products/[slug]`
- ตะกร้า และ `/checkout` (`CheckoutView`)
- `/order/[code]` อัปสลิป (`OrderView`)
- `/check-order` และ `/check-order/fp28`
- หน้า maintenance, navbar, footer, แถบประกาศ, แถบโหมดดูตัวอย่าง

**เกณฑ์ผ่าน:**
- ไม่มีการเลื่อนแนวนอน
- ปุ่มและลิงก์มีพื้นที่กดอย่างน้อย 44px
- ตัวอักษรไม่เล็กเกินอ่าน
- ฟอร์มไม่ทำให้ iOS ซูมหน้า (ตัวอักษรใน input ≥ 16px)
- sticky bar ไม่บังเนื้อหา

ผู้สร้างแยกส่วนนี้เป็นเฟสท้ายของแผนได้ แต่ต้องอยู่ในงานนี้ ให้จดผลตรวจรายหน้า (ก่อน/หลัง) ไว้ด้วย

### ขั้นออกแบบ (ผู้ใช้กำหนด)

หน้าที่ออกแบบใหม่ ได้แก่ `/products` หน้าหมวด หน้าสินค้าหลายลาย เมนูหมวดหมู่ใน admin และตารางลายใน `ProductEditor` ต้องออกแบบใน **Claude Design** (Artifact ประเภท Design บน claude.ai) ก่อนเขียนโค้ด และให้ผู้ใช้ดูและอนุมัติแบบก่อน
- mockup ใน `.superpowers/` เป็นแค่โครง ไม่ใช่แบบจริง
- เป้าหมายคือหน้าตาที่ดูตั้งใจออกแบบ แนวเว็บ Apple ใช้รูปสินค้าจริง ช่องไฟกว้าง ตัวอักษรเป็นลำดับชัด ไม่ใช่การ์ดกล่องโค้งไล่สีแบบที่ AI มักทำ
- ยังต้องใช้ระบบสี มุมโค้ง และฟอนต์ของร้านที่มีอยู่ (`--accent*`, `--radius-scale`, ฟอนต์ที่ staff เลือก)

## หลังร้าน (`/admin`)

### เมนูใหม่ "หมวดหมู่"

- **หน้ารายการหมวด:** แต่ละแถวมีรูปปก ชื่อ ลิงก์ จำนวนสินค้า และสถานะแสดง/ซ่อน
  - ลากเพื่อเรียงลำดับ ลำดับนี้ใช้กับแถบหมวดบนหน้าร้าน
  - มีปุ่ม "+ เพิ่มหมวด"
- **ฟอร์มหมวด:**
  - ชื่อไทย และชื่ออังกฤษ
  - ชื่อในลิงก์ (slug): ตั้งครั้งเดียว ทำแบบเดียวกับ slug ของสินค้า
  - ข้อความบนปก ไทยและอังกฤษ
  - รูปปก: อัปโหลดด้วยกลไกเดียวกับรูปสินค้า
  - แสดง/ซ่อน
- **ความหมายของการซ่อน (ผู้ใช้ตัดสิน):** หมวดหายจากแถบหมวด การ์ดปก และบล็อกหน้าแรก แต่สินค้าข้างในยังแสดงใน "ทั้งหมด" ยังเปิดหน้าสินค้าได้ และยังซื้อได้ ไม่ต้องเพิ่มการเช็คหมวดตอนสร้างออเดอร์ หน้าหมวดที่ถูกซ่อนเปิดตรงๆ แล้วได้ 404
- **ลบหมวดที่ยังมีสินค้า:** ต้องถามยืนยันด้วย `useConfirm()` สินค้าในหมวดนั้นจะกลายเป็น "ไม่มีหมวด" ห้ามลบสินค้าไปด้วย

### หน้าแก้สินค้า (`ProductEditor`)

ลำดับขั้นเดิมไม่เปลี่ยน แก้แค่ 2 ขั้น

**① ข้อมูลสินค้า**
- เพิ่มชื่ออังกฤษ ช่องชื่อเดิมกลายเป็นชื่อไทย
- เพิ่ม dropdown เลือกหมวด เลือก "ไม่มีหมวด" ได้

**③ ตัวเลือก ราคา และสต็อก**
- เพิ่มตัวเลือกด้านบนว่าสินค้าเป็นแบบ **"ไซซ์ / สี"** หรือ **"หลายลาย"**
- **แบบไซซ์ / สี:** UI เดิมทุกอย่าง
- **แบบหลายลาย:**
  - มีช่องราคาเดียวใช้กับทุกลาย
  - ตารางลายมีคอลัมน์ รูป · ชื่อไทย · ชื่ออังกฤษ · ตัวย่อ · สต็อก · ลบ
  - มีปุ่ม "+ เพิ่มลาย" และลากเรียงลำดับได้
  - รูปของลายอัปโหลดได้ทีละแถว
  - ตัวย่อห้ามซ้ำกันในสินค้าเดียวกัน
- **เปลี่ยนประเภทของสินค้าที่มีออเดอร์แล้ว:** ผู้สร้างเลือกเองว่าจะห้ามหรือเตือน แต่ห้ามทำให้ออเดอร์เดิมเสีย

ขั้นอื่น (รูปรวม ข้อมูลผู้ซื้อ สถานะการขาย) เหมือนเดิม

### หน้าออเดอร์และภาพรวม

แสดงชื่อจาก snapshot หลังร้านเป็นภาษาไทย (คอลัมน์เดิม) ตัวกรองตามหมวดยังไม่ทำ

### ตกแต่งหน้าแรก

เพิ่มบล็อกใหม่ "หมวดหมู่" ที่แสดงการ์ดปกหมวด staff จะได้วางไว้ที่หน้าแรกได้
- ต้องเพิ่มใน `HOME_BLOCK_TYPES` (`server/store/home.py`) และ `HomeBlocks.tsx`
- ฟอร์มของบล็อกเลือกได้ว่าจะแสดงหมวดไหนบ้าง หรือแสดงทั้งหมด

## ข้อมูล / backend

- **ตารางหมวด:** ตารางใหม่ `store_categories` มี id, slug, ชื่อไทย/อังกฤษ, ข้อความปกไทย/อังกฤษ, รูปปก, แสดง/ซ่อน, ลำดับ, created/updated
- **คอลัมน์ใหม่ใน `store_products`:**
  - `category_id` (null = ไม่มีหมวด)
  - ชื่ออังกฤษ
  - ประเภทตัวเลือก (`options` / `designs` หรือชื่ออื่นที่ผู้สร้างเลือก)
- **คอลัมน์ใหม่ใน `store_variants`:** สำหรับลาย มีชื่อไทย ชื่ออังกฤษ ตัวย่อ และรูป
  - ลายใช้แถว variant เดิม จะได้ใช้ระบบตัดสต็อก ตะกร้า และ order item เดิมได้ทั้งหมด
  - จะเก็บชื่อไทยใน `color` หรือแยกคอลัมน์ ผู้สร้างเลือกเอง แต่ข้อมูลเดิมต้องไม่เปลี่ยนความหมาย
- **migration:** ทำแบบเดียวกับที่ `db.py` ทำอยู่ คือ `ALTER TABLE … ADD COLUMN` แบบ idempotent
  - **ห้ามแก้หรือลบข้อมูลออเดอร์เดิม**
  - ก่อน deploy ต้อง backup production DB ด้วย `sqlite3 .backup()` ตามกฎใน CLAUDE.md
- **API สาธารณะ:**
  - `/v2/products` ส่งข้อมูลหมวด ชื่อ 2 ภาษา และลายพร้อมรูปกับตัวย่อออกมาด้วย
  - เพิ่ม endpoint รายการหมวดที่แสดงอยู่ หรือแนบไปกับ `/v2/meta` ผู้สร้างเลือกเอง
- **API admin:** CRUD หมวดใต้ `/v2/admin/categories*` บันทึก audit ด้วย `log_audit()` เหมือนส่วนอื่น
- **Type:** ใส่ใน `src/types/store.ts`
- **โครงสร้างไฟล์:** `server/store/db.py` ยาว 799 บรรทัดแล้ว logic หมวดควรอยู่ในโมดูลใหม่ เช่น `server/store/categories.py` ตามกฎข้อ 2 ใน CLAUDE.md

## สินค้าที่มีอยู่แล้ว

**การตัดสินใจของผม:** สินค้าเดิมทั้งหมดเริ่มเป็น "ไม่มีหมวด" และประเภท "ไซซ์ / สี" ชื่อเดิมกลายเป็นชื่อไทย ชื่ออังกฤษเว้นว่าง
- สินค้าที่ไม่มีหมวดยังเห็นได้ในหน้า "ทั้งหมด" แต่ไม่อยู่ในหมวดไหน
- staff ค่อยไปตั้งหมวดเองหลัง deploy

## ข้อจำกัด

- ทำตามกฎ clean code ข้อ 3.5 ใน `CLAUDE.md` ทั้งหมด
  - ใช้ helper เดิม (`StoreError`, `clean_text`, `adminFetch`, `Card` / `Field` / `Button`, `useConfirm`, `useStoreText`)
  - ไฟล์ไม่ยาวเกิน ~400 บรรทัด
  - แก้ logic ต้องแก้ test ในงานเดียวกัน
  - ต้องผ่าน `ruff check server tests`, `npm run lint`, `tsc` และ test ทุกชุด
- **สีและมุมโค้ง:** สีหลักใช้ `apple-blue*` มุมโค้งใช้ `rounded-*` และ `rounded-circle` ห้าม hardcode สีหรือค่า `rounded-[..]`
- **deploy:**
  - แตะทั้ง `server/` และ `src/` จึงต้องใช้ `./deploy.sh` (ทั้งคู่)
  - backup production DB ด้วย `sqlite3 .backup()` ก่อน เพราะงานนี้เพิ่มคอลัมน์ในตารางออเดอร์
  - ระหว่าง deploy ลูกค้าเห็นหน้า "Unable to connect" ได้ ควร deploy ตอนร้านปิด
- **รูป:** ใช้ระบบอัปโหลดและเสิร์ฟรูปเดิม (`/product-images/[name]`)

## รายละเอียดที่ผมตัดสินเอง (จากการ review)

- **ไอคอนในแถบหมวด:** ใช้รูปปกย่อ ฟอร์มหมวดไม่มีช่องไอคอนแยก (emoji ใน mockup เป็นแค่ตัวแทน)
- **slug ของหมวด:** ถ้าไม่กรอก ให้สร้างจากชื่ออังกฤษ เพราะ `slugify` เดิมแปลงชื่อที่เป็นภาษาไทยล้วนออกมาเป็น "product"
- **นอกหน้าหมวด:** ในหน้า "ทั้งหมด" และบล็อกหน้าแรก สินค้าหลายลายแสดงเป็นการ์ดเดียว แตกเป็นลายละใบเฉพาะในหน้าหมวด
- **สินค้าที่ไม่มีหมวด:** ต้องยังแสดงใน "ทั้งหมด" เพราะวันที่ deploy สินค้าทุกชิ้นยังไม่มีหมวด
