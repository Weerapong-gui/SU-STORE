# ใบเสร็จรับเงินสำหรับร้านใหม่ (store v2)

วันที่: 2026-10-15 · สถานะ: อนุมัติแล้ว (2026-10-15)

## ทำไม

ระบบพิมพ์ใบเสร็จตอนนี้ใช้ได้เฉพาะออเดอร์ FP28 เดิม (`claim_station.html`, `admin.html` อ่านจากตาราง `orders`) ออเดอร์ของร้านใหม่ (`SU…` ใน `store_orders`) ออกใบเสร็จไม่ได้เลย ระบบเดิมยังมีปัญหา 4 เรื่อง:
- **ค่าตั้งไม่ถูกบันทึกที่ server:** ทุกเครื่องกลับไปใช้ค่าที่ hardcode ไว้ (`RCPT_DEFAULTS`)
- **เลขที่ใบเสร็จนับแยกในแต่ละเครื่อง:** โหมด `local` เก็บใน localStorage
- **ตั้งตำแหน่งข้อความยาก:** ต้องพิมพ์ตัวเลข X/Y ทีละช่อง แล้วพิมพ์ออกมาเทียบกระดาษหลายรอบกว่าจะลงช่อง
- **ชื่อผู้รับเงินและลายเซ็นฝังอยู่ในไฟล์ `receipt_template.svg`:** เปลี่ยนคนรับเงินทีต้องให้ dev แก้ไฟล์

ลูกค้ามารับของที่จุดรับแล้ว staff พิมพ์ใบเสร็จให้ ลูกค้าเอาใบเสร็จไปใช้ต่อ เช่น เบิกเงิน เลขที่ใบเสร็จจึงต้องเชื่อถือได้

## เป้าหมาย

1. staff พิมพ์ใบเสร็จให้ออเดอร์ `SU…` ได้จากหลังร้านใหม่ (`sumfu.store/admin`)
2. เลขที่ใบเสร็จออกจาก server ชุดเดียวทั้งร้าน เรียงต่อเนื่อง ไม่ซ้ำ พิมพ์ซ้ำได้เลขเดิม
3. admin ตั้งค่าใบเสร็จเองได้ ค่าที่ตั้งบันทึกที่ server ทุกเครื่องเห็นค่าเดียวกัน
   - ชื่อผู้รับเงิน
   - รูปลายเซ็น
   - ตัวหน้าเลขที่
   - ตำแหน่งข้อความแต่ละช่อง
4. ตั้งตำแหน่งแบบเห็นผลทันที (ลากวาง) สิ่งที่เห็นในหน้าตั้งค่าตรงกับที่พิมพ์ออกมา จะได้ไม่ต้องพิมพ์ทดลองหลายรอบ

## ไม่ทำ (non-goals)

- ไม่แตะใบเสร็จ FP28 ใน claim station และ `admin.sumfu.xyz` ให้ทำงานเหมือนเดิม
- ไม่รีเซ็ตเลขตามปีหรือรอบ เพราะผู้ใช้จะใช้ระบบนี้แค่ปีเดียว
- ไม่ใส่หมวดหมู่ลงในเลขที่ใบเสร็จ (ผู้ใช้ถอนข้อเสนอนี้แล้ว)
- ไม่ส่งใบเสร็จทางอีเมลหรือ PDF ให้ลูกค้าเอง ในงานนี้ใช้การพิมพ์ที่จุดรับเท่านั้น
- ไม่เปลี่ยนหน้าตาของแบบใบเสร็จ ใช้กรอบ โลโก้ และข้อความหัวของ `receipt_template.svg` เดิม

## ห้ามเกิด (anti-goals)

- **เลขซ้ำหรือเลขกระโดด:** ห้ามเกิดแม้ staff 2 คนกดพิมพ์พร้อมกัน
- **พิมพ์ซ้ำแล้วได้เลขใหม่:** ห้ามเกิด
- **ข้อความล้นหรือไม่ลงช่อง ทั้งที่หน้าตั้งค่าบอกว่าลงแล้ว:** ห้ามเกิด
- **ออกใบเสร็จให้ออเดอร์ที่ยังไม่จ่ายเงินหรือถูกยกเลิก:** ห้ามเกิด
- **กระทบข้อมูลออเดอร์เดิม:** ห้ามเกิด

## พฤติกรรม

### เลขที่ใบเสร็จ

- **รูปแบบ:** `<prefix><เลขเรียง 4 หลัก>` เช่น `SU-R2569-0001`
  - prefix ตั้งได้ในหน้าตั้งค่า ค่าเริ่มต้น `SU-R2569-`
  - ใส่ `-R` ไว้ให้ต่างจากเลขออเดอร์ `SU2610-0001` (การตัดสินใจของผม ผู้ใช้เห็นข้อเสนอนี้แล้ว แก้ prefix ได้)
- **ออกเลขที่ server** ใน transaction เดียวกับการบันทึกใบเสร็จ ใช้ `BEGIN IMMEDIATE` แบบเดียวกับ `next_order_code` เพื่อไม่ให้ชนกัน
- **เลขผูกกับออเดอร์:** ออกเลขตอนกดพิมพ์ครั้งแรก กดพิมพ์ซ้ำได้ใบเดิม เลขเดิม และมีคำว่า "สำเนา / COPY" กำกับ
- **ยกเลิก:** admin ยกเลิกใบเสร็จได้ ต้องใส่เหตุผล
  - ใบที่ยกเลิกยังอยู่ในระบบพร้อมเลขเดิม
  - ออเดอร์นั้นออกใบใหม่ได้ด้วยเลขถัดไป
  - บันทึก `log_audit` ทั้งการออกและการยกเลิก
- **เปลี่ยน prefix หลังมีใบเสร็จแล้ว:** มีผลเฉพาะใบใหม่ ใบเดิมเก็บเลขเต็มไว้แล้ว (เป็น snapshot)

### ออกได้เมื่อไหร่

- **สถานะที่ออกได้:** `paid`, `ready`, `completed`
- **สถานะที่ออกไม่ได้:** `pending_payment`, `waiting_confirm`, `cancelled`
  - server ตอบ `StoreError(400, "ออกใบเสร็จได้เฉพาะออเดอร์ที่ชำระเงินแล้ว")`
  - UI ไม่แสดงปุ่มพิมพ์ในสถานะเหล่านี้

### ออเดอร์เปลี่ยนสถานะหลังออกใบเสร็จ (ผู้ใช้ตัดสิน: ขึ้นเตือน)

ถ้าออเดอร์ที่มีใบเสร็จที่ยังไม่ยกเลิก ถูกเปลี่ยนเป็น `cancelled` หรือสถานะใดที่ออกใบเสร็จไม่ได้:
- หน้ารายละเอียดออเดอร์แสดงแถบเตือนว่า "ออเดอร์นี้ถูกยกเลิกแต่ใบเสร็จ SU-R2569-xxxx ยังใช้งานอยู่" พร้อมปุ่มยกเลิกใบเสร็จ
- หน้ารายการออเดอร์มีป้ายเตือนบนแถวนั้น
- คำเตือนคำนวณตอนอ่านข้อมูล (ออเดอร์ที่ไม่ใช่ paid/ready/completed + ใบเสร็จที่ยังไม่ยกเลิก) ไม่ต้องแก้โค้ดเปลี่ยนสถานะออเดอร์ใน `db.py`

### เนื้อหาใบเสร็จ

**Snapshot ตอนออกใบเสร็จ** ต้องเก็บไว้ ใบเสร็จที่พิมพ์ซ้ำต้องได้ข้อมูลเดิม แม้ออเดอร์หรือค่าตั้งเปลี่ยนไปแล้ว:
- เลขที่ใบเสร็จ
- วันที่ (ใช้วันที่ออกใบเสร็จ เวลาไทย)
- ชื่อลูกค้า รหัสนักศึกษา และสำนักวิชา ตามที่ staff ยืนยันในหน้าต่างออกใบเสร็จ (ค่าเริ่มต้นมาจาก `customer_json`)
- รายการสินค้า: แต่ละแถวมีลำดับ ชื่อ (`product_name` + `variant_label` ภาษาไทย) จำนวน ราคาต่อหน่วย และจำนวนเงิน
- ยอดรวม และจำนวนเงินเป็นตัวอักษรไทย (ใช้ logic เดียวกับ `toBahtText` ใน `claim_station.html`)
- ชื่อผู้รับเงิน และรูปลายเซ็น ณ ตอนออก

ส่วนตำแหน่งข้อความไม่ต้อง snapshot ตอนพิมพ์ซ้ำใช้ค่าตำแหน่งปัจจุบัน

**แบบใบเสร็จ:**
- ใช้ `receipt_template.svg` เดิม
- เอาชื่อ "นาย บัลลังก์ วงศ์ษารัตน์" และลายเซ็นที่ฝังอยู่ออกจากไฟล์ แล้ววางจากค่าตั้งแทน
- ไฟล์เดิมยังใช้กับ claim station อยู่ จึงต้องทำสำเนาใหม่สำหรับ store v2 ห้ามแก้ไฟล์ที่ FP28 ใช้
- ใบเสร็จมี 2 ฉบับคู่กัน ซ้ายและขวา (ต้นฉบับ/สำเนา) ใช้ค่า `rightCopyOffset` แบบเดิม

**รายการสินค้าเป็นตาราง:**
- ทุกแถวใช้ตำแหน่งคอลัมน์ชุดเดียวกัน 5 คอลัมน์: เลขที่ / รายการ / จำนวน / ราคา / จำนวนเงิน
- คอลัมน์ตัวเลขชิดขวา
- ชื่อที่ยาวเกินความกว้างคอลัมน์ "รายการ" ตัดขึ้นบรรทัดใหม่ภายในคอลัมน์ และนับเป็นความสูงของแถวนั้น

**รายการเกินใบ:**
- ขึ้นใบที่ 2, 3, … ทุกใบใช้เลขที่เดียวกันและมี "หน้า n/N"
- ยอดรวมและจำนวนเงินตัวอักษรอยู่เฉพาะใบสุดท้าย
- จำนวนแถวต่อใบคำนวณจากค่าตำแหน่ง (แถวแรก ระยะห่าง และขอบล่างของตาราง)

### หน้าที่ admin ใช้

**ปุ่มพิมพ์ใบเสร็จ:** อยู่ในหน้ารายละเอียดออเดอร์ `/admin/orders/[code]`
- ออเดอร์ที่ยังไม่มีใบเสร็จ: ปุ่ม "ออกใบเสร็จ" กดแล้วเปิดหน้าต่างยืนยันข้อมูลก่อนออกเลข
  - ช่องชื่อลูกค้า รหัสนักศึกษา และสำนักวิชา กรอกค่าจากออเดอร์ไว้ให้แล้ว staff แก้หรือพิมพ์เติมได้ ช่องสำนักวิชาเป็น dropdown จาก `SCHOOL_OPTIONS` ที่มีอยู่
  - ค่าที่ staff ยืนยันจะเข้าไปอยู่ใน snapshot ของใบเสร็จเท่านั้น **ไม่แก้ `customer_json` ของออเดอร์**
  - ถ้าช่องไหนว่าง แสดงคำเตือนว่าใบเสร็จอาจใช้เบิกเงินไม่ได้ แต่ยังออกได้
  - กดยืนยันแล้วจึงออกเลขและเปิดหน้าพิมพ์
- ออเดอร์ที่มีใบเสร็จแล้ว: แสดงเลขที่กับวันที่ออก มีปุ่ม "พิมพ์ซ้ำ (สำเนา)" และ "ยกเลิกใบเสร็จ" (ใช้ `useConfirm` และมีช่องเหตุผล)
- ใบที่ยกเลิกแล้วแสดงเป็นประวัติ

**หน้า "ตั้งค่าใบเสร็จ":** เป็นแท็บหรือการ์ดในหน้า `/admin/settings` หรือหน้าแยก ให้ผู้สร้างเลือก
- **ตัวอย่างใบเสร็จจริง:** แสดงฉบับซ้าย ใส่ข้อมูลตัวอย่าง หรือข้อมูลจากออเดอร์ที่ชำระแล้วล่าสุด
- **ช่องข้อความเดี่ยว** (วันที่, เลขที่, ชื่อลูกค้า, รหัสนักศึกษา, สำนักวิชา, รวมเป็นเงิน, รวมทั้งสิ้น, จำนวนเงินตัวอักษร, ชื่อผู้รับเงิน, ลายเซ็น):
  - ลากด้วยเมาส์หรือนิ้วได้
  - ขยับทีละนิดด้วยปุ่มลูกศรบนจอ (≥44px) หรือปุ่มลูกศรบนคีย์บอร์ด
  - ปุ่ม A− / A+ ปรับขนาดตัวอักษร
  - ลายเซ็นปรับขนาดรูปได้
- **ตาราง:**
  - เส้นคอลัมน์ 5 เส้น ลากซ้าย-ขวาได้ แต่ละเส้นมีความกว้างของคอลัมน์ด้วย
  - ปุ่มขยับแถวแรก และปุ่มปรับระยะห่างแถว
  - แสดง "ใบหนึ่งใส่ได้ N แถว"
- **ผู้รับเงิน:** ช่องชื่อ และปุ่มอัปโหลดรูปลายเซ็น (PNG พื้นใส) ใช้ระบบอัปโหลดรูปเดิม `/v2/admin/images`
- **เลขที่:** ช่อง prefix และแสดง "ใบถัดไป: …"
- **ปุ่ม:**
  - "บันทึก" เก็บที่ server
  - "พิมพ์ทดสอบ" พิมพ์ด้วยข้อมูลตัวอย่าง ไม่ออกเลขจริง และมีลายน้ำ "ตัวอย่าง"
  - "คืนค่าเริ่มต้น" ใช้ `useConfirm`
- **ค่าเริ่มต้นของตำแหน่ง:** ใช้ค่าจาก `RCPT_DEFAULTS` เดิม ซึ่งลงช่องอยู่แล้ว แปลงมาเป็นหน่วยของระบบใหม่

**หลักสำคัญ (ทำให้ไม่ต้องพิมพ์เทียบ):** ตัวอย่างในหน้าตั้งค่าต้อง render ด้วยโค้ดชุดเดียวกับตอนพิมพ์จริง คือฟังก์ชันเติม SVG เดียวกัน ห้ามมีโค้ด render 2 ชุด

### การพิมพ์

- เปิดหน้าพิมพ์ที่ render SVG เต็มใบ แล้ว `window.print()` แบบเดียวกับระบบเดิม
- ขนาดกระดาษเป็นไปตาม viewBox เดิม (812.98 × 597.12) ใส่ CSS `@page` ให้ไม่มี margin หรือ scale จาก browser มาทำให้ตำแหน่งเพี้ยน
- ฟอนต์ไทยใช้ SukhumvitSet (`/fonts/SukhumvitSet.ttc`) ตามเดิม ถ้าหน้าร้าน Next ต้องเสิร์ฟเอง ผู้สร้างเลือกได้ว่าจะ proxy หรือคัดลอกไฟล์

## ข้อมูล / backend

- **ตารางใหม่ `store_receipts`:**

  - snapshot_json (ข้อมูลตาม "เนื้อหาใบเสร็จ")
  - cancelled_at, cancelled_by, cancel_reason
  - มี partial unique index ให้ 1 ออเดอร์มีใบเสร็จที่ยังไม่ยกเลิกได้แค่ 1 ใบ
- **ตัวนับ:** ใช้ `store_counters` เดิม คีย์เช่น `receipt` หรือตารางตัวนับแยก ผู้สร้างเลือกเอง แต่เลขต้องไม่ซ้ำและไม่ข้าม
- **ค่าตั้งใบเสร็จ:** เก็บใน `store_settings` คีย์ `receipt` เป็น JSON มี payee name, signature url, prefix และตำแหน่งทุกช่อง ตรวจรูปแบบด้วย `clean_text` / `as_int` / `clean_image_url`
- **โมดูลใหม่ `server/store/receipts.py`:** อย่าเพิ่มลงใน `db.py` ซึ่งยาวแล้ว
- **Route admin:**
  - `GET/PUT /v2/admin/receipt-settings`
  - `POST /v2/admin/orders/<code>/receipt` ออกใบเสร็จ หรือคืนใบเดิมถ้ามีแล้ว
  - `GET /v2/admin/orders/<code>/receipts` ประวัติ
  - `POST /v2/admin/receipts/<id>/cancel`
  - `GET` แบบใบเสร็จ SVG สำหรับ store v2
- **ข้อมูลออเดอร์:** ห้ามแก้ `store_orders` / `store_order_items` และห้ามเปลี่ยน schema ของตารางออเดอร์เดิม เพิ่มได้แค่ตารางใหม่ ก่อน deploy ต้อง backup DB
- **วันที่:** เก็บ UTC แล้วแสดงเป็นเวลาไทย ตามกฎ timezone ใน `CLAUDE.md`

## รายละเอียดที่ผมตัดสินเอง (จากการ review)

- **ยอดเงิน:** "รวมเป็นเงิน" กับ "รวมทั้งสิ้น" ใช้ยอดเดียวกันจาก `total_amount` ของออเดอร์ เพราะร้านใหม่ไม่มีส่วนลดหรือค่าส่ง และ `create_order` คิดยอดจากผลรวมของรายการ (`db.py` ~623)
- **ชื่อลูกค้า:** ใช้ `customer.name`
- **1 ออเดอร์ = 1 ใบเสร็จ:** ออกครั้งเดียวทั้งออเดอร์ ไม่ออกตามการรับของทีละส่วน
- **สิทธิ์:** staff ทุกคนที่ login หลังร้านออกใบเสร็จและพิมพ์ซ้ำได้ ส่วนการยกเลิกใบเสร็จและการแก้ค่าตั้งใบเสร็จ ต้องเป็น `is_superadmin` เพราะใบเสร็จใช้เบิกเงิน
- **ตัวอย่างในหน้าตั้งค่า:** ใช้ข้อมูลสมมติ ไม่ดึงข้อมูลลูกค้าจริง
