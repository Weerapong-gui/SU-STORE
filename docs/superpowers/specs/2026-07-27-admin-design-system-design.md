# ระบบดีไซน์ของหน้า admin (ก้อน 1 จาก 5)

วันที่: 2026-07-27
สถานะ: design ผ่านการอนุมัติแล้ว รอเขียนแผน implement

---

## 1. ปัญหา

หน้า admin (`server/templates/admin.html`) ใช้งานได้แต่ "ดูไม่สวยและเข้าใจยาก" ทั้งสามด้านพร้อมกัน: หน้าตารก หาของข้ามแท็บไม่เจอ และไม่มีเอกลักษณ์

สภาพไฟล์ที่วัดได้: **187,655 ตัวอักษร / 3,283 บรรทัด** ในไฟล์เดียว — CSS 12,841 ตัวอักษร, JavaScript 136,706 ตัวอักษรในบล็อกเดียว, 8 แท็บ (orders, products, analytics, settings, audit, backup, feedback, users), 43 CSS class

กำแพงที่แท้จริงของงานนี้: **`style=` แบบ inline 380 จุด รวม 22,519 ตัวอักษร (~12% ของไฟล์)** — 218 จุดอยู่ใน markup นิ่ง อีก 162 จุดถูกต่อขึ้นตอนรันใน JavaScript เทียบกับ `class=` เพียง 263 จุด inline ชนะ CSS ทุกกรณี ระบบ token จึงไม่มีผลถ้าไม่ถอด inline ควบคู่กันไป

แรงบันดาลใจที่เจ้าของงานส่งมา: [Designing Dashboard UI in Figma (Community)](https://www.figma.com/design/7MCMD73jFvtxdQ5bk0Xaeq/Designing-Dashboard-UI-in-Figma--Interactive-UX-Tutorial-for-Beginners--Community-?node-id=0-1) — dashboard พื้นเข้ม การ์ดลอยมนใหญ่ ตัวเลข hero ใหญ่ ปุ่มทรงแคปซูล พาเลตต์ขาว-ดำ-เทา

## 2. การแตกโปรเจกต์

งาน "รื้อ UI ใหม่ทั้งหน้า" ใหญ่เกินหนึ่ง spec แตกเป็น 5 ก้อน ทำเรียงกัน แต่ละก้อนส่งมอบของที่ใช้งานได้จริง:

| # | ก้อน | สถานะ |
|---|---|---|
| **1** | **ระบบดีไซน์พื้นฐาน — token + คอมโพเนนต์ + ถอด inline โซนหลัก** | **spec นี้** |
| 2 | โครงนำทาง — sidebar แทนแท็บ 8 อัน + แถบหัวใหม่ | ยังไม่เริ่ม |
| 3 | แท็บ Orders — ตาราง ฟิลเตอร์ bulk bar เชิงลึก | ยังไม่เริ่ม |
| 4 | แท็บ Analytics — กราฟและการ์ด | ยังไม่เริ่ม |
| 5 | แท็บที่เหลือ + modal ทั้งหมด | ยังไม่เริ่ม |

ก้อน 1 มาก่อนเพราะทำให้ก้อน 2-5 เหลือแค่งานจัดวาง ไม่ต้องตัดสินใจเรื่องสี ระยะ ความมน ซ้ำทุกครั้ง

## 3. นอกขอบเขตของ spec นี้

- ไม่ย้ายอะไร ไม่เปลี่ยนโครงหน้า (แท็บยังเป็นแท็บ) — นั่นคือก้อน 2
- ไม่แตะ modal แก้ไขออเดอร์, แท็บ products/analytics/settings/audit/backup/feedback/users — ก้อน 4-5
- ไม่แยกไฟล์ `admin.css` / `admin.js` — ทำตอนก้อน 2 ที่ต้องรื้อโครงอยู่แล้ว จะได้ผ่าไฟล์ตอนมีเหตุผลอื่นประกอบ
- ไม่แตะฝั่ง server, API, ฐานข้อมูล, `claim_station.html`, `display*.html`
- ไม่แตะการ generate ใบเสร็จ SVG (เป็นของพิมพ์ ไม่ใช่หน้าจอ)

## 4. การตัดสินใจและเหตุผล

### 4.1 ทิศทาง: แบบ A "ใกล้ของอ้างอิง"

เทียบ 3 แบบด้วย mockup ที่ใช้ข้อมูลจริงของระบบ เจ้าของงานเลือก A — การ์ดมน 20px, ตัวเลข hero 44px น้ำหนัก 800, ปุ่มทรงแคปซูล, การ์ดลอยบนพื้นเข้ม

### 4.2 พาเลตต์: เทาเป็นพื้น สีเฉพาะสถานะ

โครงหน้า/การ์ด/ตาราง/ปุ่มเป็นเทาล้วนตามของอ้างอิง แต่**ไม่ยกความเป็นขาว-ดำล้วนมาทั้งหมด** เพราะ staff อ่านสถานะจากสีก่อนอ่านตัวหนังสือ — สีจึงถูกสงวนไว้ให้ badge และตัวเลขสถานะเท่านั้น ผลพลอยได้คือสีเด่นขึ้นกว่าเดิมเพราะรอบข้างเงียบ

### 4.3 ความหนาแน่น: โซนสรุปโปร่ง โซนตารางแน่น

ของอ้างอิงเป็น dashboard ส่วนตัวที่ข้อมูลน้อย ส่วน admin นี้เป็นเครื่องมือปฏิบัติการ — ตาราง 50 แถวต่อหน้า 66 หน้า ใช้ตอนมีคนต่อแถวรอ ถ้ายกความโปร่งของอ้างอิงมาทั้งหน้าจะเห็นแถวต่อจอน้อยลงและงานช้าลง จึงแยกสองมาตรฐาน: การ์ดสรุปใช้ระยะ 20/24 ตารางใช้ 8/12

### 4.4 ธีม: dark อย่างเดียว ตัด light ทิ้ง

token เหลือชุดเดียว งานและโอกาสพลาดลดครึ่ง แลกกับการอ่านกลางแดดที่แย่ลงและคนที่เคยตั้ง light ไว้จะโดนเปลี่ยน — ข้อแลกเปลี่ยนนี้แจ้งแล้วและเจ้าของงานเลือกเอง

### 4.5 แนวทางลงมือ: token + ถอด inline เฉพาะโซนหลัก

ทางเลือกที่พิจารณา:
- **ทาสีที่ CSS อย่างเดียว** — เสี่ยงต่ำสุด เร็วสุด แต่ inline 12% ยังค้างอยู่และดันเป็นตัวที่นิยามหน้าตาแบบ A พอดี ผลลัพธ์จะใหม่ครึ่งเดียว
- **แยกไฟล์ก่อนค่อยแต่ง** — แก้รากปัญหาไฟล์ 187k และให้เบราว์เซอร์ cache ได้ แต่ต้องเพิ่ม route ใน `order_api.py` กระทบ deploy และมี commit เชิงกลไกก้อนใหญ่ก่อนเห็นผลทางสายตา
- **เลือก: token + ถอด inline 48 จุดในโซนที่กำหนดหน้าตา** — ดีไซน์ลงจริงตรงที่คนมอง โดยแตะ JS เท่าที่จำเป็น

### 4.6 การตั้งชื่อ: ตามของเดิม ไม่เอา BEM

โค้ดเดิมใช้ `base + modifier` เว้นวรรคอยู่แล้ว (`stat compact`, `stat stat-ring`, `ghost phase-btn active-phase`) ใช้แบบเดียวกันต่อ และ**ห้ามเปลี่ยนชื่อ class เดิม** (`stat`, `badge`, `toolbar`, `table-card`, `notice`) — การ rename จะลากไปแตะโค้ดที่ไม่ได้ตั้งใจแก้ ทำให้อ่าน diff ไม่ออกว่าอะไรคือดีไซน์ อะไรคือ rename

### 4.7 จังหวะ deploy: ปล่อยได้ทันที

ความเสี่ยงจริงไม่ได้อยู่ที่โค้ด (แตะแค่ CSS/markup ผลเสียแย่สุดคือหน้าตาเพี้ยน ไม่ใช่ข้อมูลหาย) แต่อยู่ที่ staff เจอหน้าตาใหม่กลางงาน — แจ้งแล้ว เจ้าของงานเลือกปล่อยทันที

## 5. ชุด token (dark ชุดเดียว)

- ความมน: `--r-sm 8` (input) · `--r-md 12` (ปุ่ม การ์ดย่อย) · `--r-lg 20` (การ์ดใหญ่) · `--r-pill 999`
- ระยะ: `4 · 8 · 12 · 16 · 20 · 24 · 32 · 40` — โซนสรุป 20/24, แถวตาราง 8/12

- ฟอนต์: **คง `Sarabun` เดิม** — ของอ้างอิงเป็นฟอนต์ละติน ใช้กับชื่อไทยไม่ได้

## 6. สัญญาของคอมโพเนนต์

งาน CSS ครอบคลุม **class เดิมทั้ง 43 ตัว** — ทุกตัวถูกจูนให้ใช้ token ชุดใหม่ รวมถึง `.tab-btn` (แถบแท็บด้านบน) ซึ่งไม่มี inline ให้ถอดแต่ต้องเปลี่ยนสีตามไปด้วย ไม่งั้นแถบแท็บจะเป็นของเก่าค้างอยู่กลางหน้าที่ใหม่หมดแล้ว ตารางข้างล่างคือตัวที่ **สัญญาเปลี่ยนหรือเพิ่มใหม่** ไม่ใช่รายชื่อทั้งหมด

| class | สัญญา |
|---|---|
| `.card` | พื้น `--surface`, มน `--r-lg`, เงา `--shadow-1`, padding 24 · `.card.tight` padding 16 |
| `.stat` | label 12 `--muted` + value 44/800 · `.compact` value 30/750 · `.ring` มีวงกลม % · `.clickable` เส้นใต้ accent + cursor · `.stat .meter` แถบ progress สูง 5px |
| `.chip` | ทรง pill พื้น `--surface-2` · `.active` พื้นสว่างตัวอักษรเข้ม |
| `.btn` | มน `--r-md` · `.primary` accent · `.ghost` โปร่งมีเส้น · `.danger` · `.pill` มน pill |
| `.badge` | ทรง pill 12px/600 + `.ok .warn .danger .accent .purple .neutral` จับคู่สีอักษร/พื้นจางตามตาราง §5 |
| `.table-card` | มน 20 ไม่มีกรอบนอก แถวคั่น `--line` 1px, hover `--surface-2`, หัวคอลัมน์ 11 uppercase `--faint`, cell padding 11/22 |
| `.toolbar` | แถวเครื่องมือ gap 8 จัดกลางแนวตั้ง |
| `.pager` | **ใหม่** — แถบ Prev/Next + ข้อความหน้า แทน inline ที่ `#paginationBar` |

## 7. ขอบเขตการถอด inline — 48 จาก 380 จุด

| ที่ | บรรทัด (ณ วันเขียน) | inline |
|---|---|---|
| markup นิ่ง `#orderStats` → `.table-card` (การ์ดสรุป, ชิป phase, toolbar, bulk bar, หัวตาราง) | 204–267 | 16 |
| `renderOrderStats()` | 1508–1598 | 9 |
| `renderOrders()` (markup แถว) | 1727–1847 | 22 |
| `renderPagination()` | 2097–2111 | 1 |

เลขบรรทัดจะเลื่อนเมื่อแก้ ให้ค้นด้วยชื่อฟังก์ชัน/`id` ไม่ใช่ยึดเลข

**อยู่นอกขอบเขต (332 จุด):** modal แก้ไขออเดอร์ (`#oe_*`), แท็บอื่นทั้งหมด, การ generate ใบเสร็จ

เหตุผลของเส้นแบ่ง: 48 จุดนั้นคือทุกอย่างที่เห็นเมื่อเปิดหน้า admin โดยไม่ต้องคลิกอะไร ที่เหลือต้องกดเข้าไปถึงจะเห็น

## 8. การตัด light theme

- ลบ `@media (prefers-color-scheme: dark)`, `:root[data-theme="light"]`, และชุดค่า light — เหลือ `:root` ชุดเดียว
- เพิ่ม `color-scheme: dark` ที่ `:root` เพื่อให้ scrollbar / dropdown / date picker ของเบราว์เซอร์เป็นโทนเข้มตาม ไม่ใช่กล่องขาวโผล่มา
- ลบปุ่ม toggle: markup + `initTheme()` + CSS `.theme-btn-track` / `.theme-btn-thumb` + การอ่านเขียน `localStorage.suStoreTheme` (10 จุดอ้างอิง)
- ไม่ต้อง migrate: key `suStoreTheme` ที่ค้างอยู่ในเครื่องผู้ใช้จะไม่มีใครอ่าน

## 9. การพิสูจน์ว่าไม่พัง

repo นี้ไม่มีตัวรัน JavaScript ในเทสต์ แต่ pytest อ่านเนื้อ template จาก `order_api.ADMIN_HTML` ได้ (โหลดตอน import) — วิธีนี้จับกับดักจริงได้มาแล้ว เพิ่มเทสต์ใน `server/tests/test_order_api.py` 3 กลุ่ม:

1. **light theme หายจริง** — `ADMIN_HTML` ต้องไม่มี `prefers-color-scheme`, `data-theme`, `suStoreTheme`, `theme-btn`
2. **คอมโพเนนต์มีจริงและถูกใช้** — ต้องพบ `class="stat`, `class="badge `, `class="chip`, `class="pager` ทั้งใน markup นิ่งและใน string ที่ `renderOrders`/`renderOrderStats` ต่อขึ้น
3. **inline หายจากโซนที่ประกาศ** — assert กับสตริง inline เดิมที่ระบุตัวได้ เช่น `display:flex;gap:12px;align-items:center;padding:12px 0` (pager เดิม) และ `border-bottom:2px solid var(--accent)` (การ์ดคลิกได้เดิม) — ผูกกับข้อความที่มีอยู่จริง ไม่ใช่นับจำนวนซึ่งจะเพี้ยนทุกครั้งที่แก้

**ของเดิมต้องเขียว** — เทสต์ 90 ตัวที่มีอยู่ โดยเฉพาะ `setOdom('statKhantokClaimed'`, `id="paginationBar"` ต้องอยู่เหนือ `id="ordersBody"`, และรูปแบบข้อความ pager สามอันนี้พิสูจน์ว่าการถอด inline ไม่ทำสายไฟหลุด

**ตรวจด้วยตา** (เรื่องสวยไม่มีเทสต์): หน้า Orders ทั้งตอนมีข้อมูลและตอนค้นไม่เจอ · badge ครบทุกสถานะ (พร้อมรับ / ชำระแล้ว / รอยืนยัน / ปฏิเสธ / รับแล้ว / คืนเงิน) · ชิป phase ตอน active และไม่ active · bulk bar ตอนเลือกแถว · scrollbar และ dropdown เป็นโทนเข้มหลังใส่ `color-scheme: dark`

## 10. ย้อนกลับและ deploy

แตะเฉพาะ `server/templates/admin.html` และไฟล์เทสต์ — ไม่มี migration ไม่แตะ API ไม่แตะข้อมูล
Deploy: `bash deploy-api.sh` (order-api restart ~3-5 วินาที su-store ไม่ถูกแตะ)
ย้อนกลับ: `git revert` + `bash deploy-api.sh`
