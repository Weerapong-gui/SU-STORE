## ทำไม

เจ้าของอยากให้หน้าร้านดูสะอาดและเป็นภาพมากขึ้น และให้ลูกค้าดูสินค้าแต่ละลายได้หลายมุม (ตอนนี้ลายละ 1 รูป) หน้าสินค้าแบบหลายลายตอนนี้ "โอเคแล้วทั้งคอมและมือถือ" — ห้ามเปลี่ยนส่วนอื่นนอกจากกรอบรูป

## งาน 1 · หน้า `/products` (เจ้าของตัดสินใจแล้ว)

- ลบประโยคใต้หัวข้อ "Merch from the Student Union. Order online, pick up on campus." / "ของที่ระลึกจากองค์การนักศึกษา สั่งออนไลน์ รับที่มหาวิทยาลัย" — ลบการเรียก `SectionSubtitle textKey="shopSubtitle"` ใน `src/app/(main)/products/page.tsx` และ key `shopSubtitle` ทั้งสองภาษาใน `src/lib/storeI18n.ts`
- การ์ดใน "Browse by category" (`CategoryCovers.tsx`): layout เดิมทุกอย่าง แต่พื้นแถบชื่อด้านบน (ตอนนี้ `bg-mist`) เปลี่ยนเป็น **รูปปกเดียวกันที่เบลอมาก** (ขยายเกินขอบเล็กน้อยกันขอบเบลอโปร่ง, ปรับสว่างขึ้นให้ตัวหนังสือดำอ่านออก) รูปด้านล่างคมเหมือนเดิม
- การตัดสินใจของผู้ออกแบบ: หมวดที่ไม่มีรูปปก → แถบเป็น `bg-mist` เหมือนเดิม; ตัวหนังสือยังสีดำ (`text-ink`) ตาม mock

## งาน 2 · หัวหน้าหมวด `/products/c/[category]` (เจ้าของตัดสินใจแล้ว)

- รูปปกเป็นพื้นหลัง **เต็มความกว้างจอ** ติดใต้ navbar (ไม่อยู่ใน Container) ไล่เฉด **ซ้ายมืด → ขวาสว่าง** (`linear-gradient(to right, rgba(0,0,0,.65), rgba(0,0,0,.35) 45%, rgba(0,0,0,.05) 80%)`) ชื่อหมวดตัวขาวใหญ่ชิดล่างซ้าย, tagline (ถ้ามี) ตัวขาวใต้ชื่อ
- **คอม:** "‹ Shop" สีขาวอยู่มุมบนซ้ายของรูป
- **มือถือ:** เฉพาะหน้าหมวด "‹ Shop" **สีน้ำเงิน** (`text-apple-blue`) แทนที่โลโก้ SU ใน navbar และไม่แสดงในรูป; ตะกร้า/เมนูอยู่ที่เดิม; หน้าอื่นทั้งหมดและคอมยังเป็นโลโก้
- ช่องค้นหา sticky และ grid สินค้าใต้รูปคงเดิม (รูปปกเดิมทางขวาบนคอมถูกแทนด้วย hero นี้ จึงลบออก)
- การตัดสินใจของผู้ออกแบบ: ใต้ชื่อแสดงจำนวนลาย (ข้อความเดิม `t.designTotal`) เมื่อไม่มี tagline; หมวดที่ไม่มีรูปปก → หัวข้อแบบเดิม (ตัวดำบนพื้นขาว, "‹ Shop" ตามแบบเดิม); ความสูง hero ประมาณ 220px มือถือ / 320px คอม

## งาน 3 · ลายละหลายรูป (เจ้าของตัดสินใจแล้ว: แบบ B)

หน้าร้าน (`ProductGallery`, ใช้ใน `ProductDetail`):
- **คอม:** รูปใหญ่อย่างเดียว ลูกศร ‹ › โผล่ตอนเอาเมาส์ชี้ (และตอน focus คีย์บอร์ด) จุดบอกตำแหน่งใต้รูป (จุดปัจจุบันยาวกว่า)
- **มือถือ:** ปัดนิ้วซ้าย/ขวา (scroll-snap) มีจุดใต้รูปและป้าย "1 / 3" มุมล่างขวาของรูป
- เปลี่ยนลาย → กลับไปรูปแรกของลายนั้น; ลายที่มีรูปเดียว → ไม่มีลูกศร/จุด/ป้าย (หน้าตาเหมือนตอนนี้)
- ปุ่มเลือกลาย, รูปในตะกร้า, รูปในออเดอร์, การ์ดสินค้า ใช้ **รูปแรก** ของลายเหมือนเดิม
- สินค้าแบบไซซ์/สี (ไม่ใช่หลายลาย) ใช้ gallery ใหม่ตัวเดียวกันกับ `product.images` ได้ (ตอนนี้มีรูปย่อ — ให้เปลี่ยนเป็นแบบ B เหมือนกัน เพื่อมี gallery แบบเดียวทั้งร้าน) — **การตัดสินใจของผู้ออกแบบ**

ข้อมูล (การตัดสินใจของผู้ออกแบบ):
- คอลัมน์ `store_variants.image` คงเดิม = รูปแรก/รูปหลัก (ทุกที่ที่ใช้อยู่ไม่ต้องแก้)
- เพิ่มคอลัมน์ `store_variants.extra_images_json TEXT NOT NULL DEFAULT '[]'` ผ่านรายการ migrate คอลัมน์ใน `server/store/db.py` (เพิ่มคอลัมน์อย่างเดียว ไม่แก้ข้อมูลเดิม ไม่แตะตารางออเดอร์)
- payload ของ variant เพิ่ม `images: string[]` = `[image, ...extra]` ที่ไม่ว่าง (คง `image` ไว้)
- admin ส่ง `images: string[]` ในแต่ละแถวลาย; server ตรวจทุก URL ด้วย `clean_image_url`, จำกัด `MAX_DESIGN_IMAGES = 8` (เกิน → `StoreError(400, "รูปลายใส่ได้ไม่เกิน 8 รูป")`), เก็บ `images[0]` ลง `image` ที่เหลือลง `extra_images_json`; ถ้า payload มีแค่ `image` (ไม่มี `images`) ให้ทำงานเหมือนเดิม
- type `StoreVariant` ใน `src/types/store.ts` เพิ่ม `images: string[]`

หลังร้าน (`src/components/admin/product/DesignsTable.tsx` + `designRows.ts`):
- ช่องรูปของแต่ละแถวลายเป็นแถวรูปเล็ก: รูปแรกมีป้าย "รูปหลัก", ปุ่ม `+` อัปโหลดเพิ่ม (ใช้ endpoint อัปโหลดเดิม `images`), แต่ละรูปลบได้ และเลื่อนซ้าย/ขวาเพื่อเรียงลำดับ, ครบ 8 รูปปุ่ม `+` หายไป
- ข้อความ UI ภาษาไทย, ยืนยันก่อนลบผ่าน `useConfirm()` ถ้ามีการลบ

## เป้าหมาย / ไม่ใช่เป้าหมาย

ไม่ใช่เป้าหมาย: เปลี่ยน layout ส่วนอื่นของหน้าสินค้า, ซูมรูป/เปิดเต็มจอ, ลากวางเรียงรูป, เปลี่ยนหน้าแรก (HomeBlocks), แก้ข้อมูลออเดอร์

Anti-goal: หน้าสินค้าที่มีลายละรูปเดียวหน้าตาเปลี่ยน; ปัดรูปบนมือถือแล้วหน้าเลื่อนแนวนอนทั้งหน้า; migration ทำให้ variant เดิมเสียรูป; ตัวหนังสือบน hero อ่านไม่ออกเพราะรูปสว่าง
